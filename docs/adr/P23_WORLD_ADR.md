## Topology (Q24 ratified: nine floating islands in a cloud sea)
- One island per existing zone (ids from beasts.json — 9 total, exact set).
- Island = one scene subtree; active + neighbors resident; others freed.
- Traversal via wind corridors between islands.
- Zone gates are PHYSICAL: mist/wind/lightning walls keyed to EXISTING
  zone min-realm data. zones3d.json does not own gate values — the
  generator INGESTS beasts.json/realms.json and emits consistent copies;
  ContentDB validation cross-checks at load (single source of truth
  remains the original tables).
- Beast presence: low-poly markers/billboards only — beasts remain codex
  entities (rule 4); no duel behavior in-world.
- Guardian shrines: visual landmark per macro-tier gate; duels resolve via
  the existing engine/UI path. Presentation only, no conflation.

## Determinism
- P23a VERIFICATION STEP: read GameEngine and confirm map_seed is stable
  for the run's lifetime. (Read-only verification already confirms:
  map_seed is written only by generate_map/apply_state.)
  terrain_seed = hash(map_seed, zone_id). NEVER an in-memory cache (breaks
  cross-session determinism).
- Same seed => identical mesh; verified by vertex-hash test. Nothing saved.

  gate {min_realm = existing zone gate data, wall_type mist|wind|lightning
  by macro tier}; spawn {pos, facing}; weather {spring, summer, autumn,
  winter} each clear|rain|snow|petal|ash; props {density, tree_style,
  rock_style, herb_nodes} — visual only.
validation (additive, M2): unknown fields reject; zone-id set match;
  gate values match existing tables; palettes complete; no new ids;
  no beast-id namespace use.
